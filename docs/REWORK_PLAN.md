# Rework plan: map generation, building logic, horde spawning (2026-11-18)

Request (the King, English): "rework the map generation and building logic and the spawning of horde". No defect or target was given, so this file records the measured baseline and the options. Nothing is changed yet.

## Baseline (v96, measured today)

| System | Probe | Result |
| --- | --- | --- |
| Horde spawn distance | `tests/spawn_probe.js`, 96 starts, 384 lanes | none within 90 tiles of its castle; shortest straight distance 109, so the v94 rule (150 path tiles, 130 straight) holds |
| Horde pace | `tests/spawn_pace.js`, wave 3, perfect defence | solo worlds 0 and 2: first contact 268 and 283 s, half the horde 355 and 367 s, wave beaten 444 and 434 s. Co-op worlds 1 and 9: beaten 310 and 406 s, no zombie reached 12 tiles of a castle |
| Lane starts | `world/routes.js` | three lanes per castle at about 120 degrees, bent by a cost map (water, height, woods), start at the world edge or at `MAPD` (World size) |
| Map | `world/terrain.js` (chunks, noise, camps, ruins, ramps) | 2250x1250 tiles fixed, generated by chunk around the castle and the lanes; saves keep the routes and the chunks already made |
| Building | `gameplay/construction.js`, `ui/build-menu.js`, `rendering/build-preview.js` | placement checks per type (`placeErr`, `valid`, tower special case), preview in 3D, cost, refund on demolition |

Pace is now consistent between worlds (the old spread 258 to 875 s is gone), so spawning is not where the biggest gap is.

## Constraints any rework must keep

- Determinism: same seed gives the same world and the same hashes in solo and co-op (`det`, `mp8`, `mpk`, `mp_soak`). A change of generation changes every pinned hash on purpose; it needs a new pin and a note.
- Saves: the save format is version 1 and old saves must load (`save` test). Routes and generated chunks are saved, so a new generator may only apply to new games.
- Co-op: the host sends the seed, the generator parameters and the world size (`w` and `s` messages); every new parameter must travel there.

## Options (to be chosen by the King)

Map generation
- M1 Start quality: score candidate castle sites (flat area, wood, stone, water, distance to lanes) instead of a random valid site. Low risk, new games only.
- M2 Points of interest: guaranteed rebel camps, ruins and resource clusters at set distances. Medium risk (camp AI and quests read them).
- M3 Real playable extent (a smaller world, not only shorter lanes): about 60 bound checks in 50 files; high risk.

Building logic
- B1 Placement feedback: tell the player why a spot is refused (slope, water, door, too close) in the preview. Low risk, UI only.
- B2 Auto-wall and path rules: wall runs with corner and gate suggestions. Medium risk (pathing and lane fields read walls).
- B3 Rules table: move the per-type checks of `build()` into one data table. Medium risk (refactor, co-op command path).

Horde spawning
- H1 Wave director: wave size and mix from the defence and the economy, not only the wave number. Changes balance, needs the King's targets.
- H2 Pincer waves: two lanes at once from different sides, with a warning. Medium risk (`waves.js`, `wave-preview.js`).
- H3 Spawn variety: elite and miner groups at their own spawn points. Low to medium risk.

## Suggested first slice

M1 + B1 + H2, in that order: none of them breaks old saves, each has a clear test (site score distribution, preview reason texts in 9 languages, wave lanes in the `waves` test). Start only after the King confirms the options or names his own.

## Decision 2026-11-18 (King): no compatibility with old saves

Old saves are hidden and everything restarts on the new system (voxel terrain, schematic buildings, portals). No save migration, no legacy code paths: a save format version gate hides saves from before the switch. Co-op hashes and `det` are simply re-pinned.
